## 2. Facts every page must reflect (the "2.0 fact sheet")
Write `docs/_snippets/facts.md` first (WP1), verified against code, and have every page agree with it:
1. **Contract**: every feature has `process(...)` (one frame/sample, streaming), `run(...)` (a whole recording), `reset()`; returns a `Result` described by the class `Schema` (`Output`s with components); `Recorder` collects results over time; `latest` gives the last result. Verify the exact names/signatures in `pyeyesweb/data_models/{results,recorder,feature}.py`.
2. **Statuses**: the `Status` values (e.g. warming up / valid / ...) — list them exactly as in code and when each happens (minimum window, insufficient data).
3. **Time rule**: all time quantities (windows, durations, timestamps) in **seconds**, never frames; `timestamp` argument.
4. **Units**: lengths in `"m"` (default, the EyesWeb numbers) or `"mm"` via `units=` for features with `_unit_params` (see `base/core_feature.py:88`); the **humanoid exception** (HumanoidSimulator/mass-spring family: state its actual unit rule from `08_humanoid.py`/CONVENTIONS).
5. **Choices**: options are plain strings (e.g. `method="..."`), booleans are bools; no enums in the public API.
6. **Constructors**: the `from_*` classmethods (list them per class via introspection).
7. **Skeletons**: presets in `pyeyesweb/skeletons.py` and `joint_map=` to map dataset labels (Qualisys example).
8. **Layers and catalog**: `catalog()`, `catalog_table()`, `Layer` enum; the five packages.
9. **Live vs structural parameters**: live = changeable while running; structural = needs a new object / reset. Source: `examples/scratch/live_parameters_classification.md`.
10. **Dropped features** (catalog 59→49→60 history: see memory/DEVELOPMENT_SPEC): at least Lightness, StatisticalMoment, Clusterability, SpeedSmoothness/Smoothness, HistogramRarity, single `Synchronization`, ZeroCross, SkeletonManipulator, GetKinematical, Trajectory — confirm the complete list from `EyesWebTD/PORTING_STATUS.md` and DEVELOPMENT_SPEC; each with "use X instead" or "removed".
11. **Fidelity policy**: ports are faithful to EyesWeb by default; where the original had a bug fixed in the C++ core it is marked **"Corrected in the core"** in the docstring and the reference page, with a one-line description of the old behaviour.
12. **Install/core**: the wheel ships the compiled core; developers set `EYESWEB_CORE_PATH`.

## 5. Docstring conventions and per-feature checklist
NumPy style. Class docstring of every catalog feature:
- one-line summary; short **what it measures** paragraph (movement meaning, not the algorithm only);
- **Parameters**: each with type, default, **unit** (s, m/mm, Hz, rad, dimensionless), allowed strings, and *(live)* or *(structural)*;
- **Inputs**: names/shapes accepted by `process` (and `run`);
- **Returns / Outputs**: each `Output` and component with unit and range;
- **Statuses**: when the result is not VALID (warm-up length in seconds, etc.);
- **Notes**: EyesWeb origin block name; "Corrected in the core: …" when applicable; known limitations;
- **References**: literature, supplied by the maintainer (placeholder `TODO(ref)` until supplied). Known: SpectralArcLength → Balasubramanian, Melendez-Calderon, Roby-Brami, Burdet (2015) "On the analysis of movement smoothness", J NeuroEng Rehabil 12:112;
- **Examples**: a ≤10-line doctest that runs (synthetic data) and is executed by `pytest --doctest-modules`.
Checklist file: `docs/dev/feature_checklist.md`; WP3 produces a table of 60 rows × these columns with ✔/✘.
