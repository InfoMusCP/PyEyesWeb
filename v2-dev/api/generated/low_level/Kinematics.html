Description#

class pyeyesweb.low_level.Kinematics(*, dims=None, input_mode='point', output_dims='tangential', output_type='velocity', filter_window_length=15, filter_polyorder=3, movement_threshold=0.005, sampling_rate=None, units='m')[source]#

Velocity, acceleration, jerk, curvature or direction of a moving point, from a Savitzky-Golay fit.

Kinematics describes how a point (a joint, a marker, the centre of mass) moves along its path; with one component it describes a scalar signal. The position samples are smoothed and differentiated in one step by a Savitzky-Golay filter: the newest filter_window_length samples are fitted by a polynomial of order filter_polyorder and the estimate is the fit, or one of its derivatives, evaluated at the centre of that window. With \(\mathbf{x}(t)\) the smoothed position, the derivatives are taken with respect to time in seconds,

\[\mathbf{v} = \frac{d\mathbf{x}}{dt}, \qquad \mathbf{a} = \frac{d^2\mathbf{x}}{dt^2}, \qquad \mathbf{j} = \frac{d^3\mathbf{x}}{dt^3},\]

and the curvature is that of the path (\(1/r\) for a circle of radius \(r\)); the direction is the unit vector of the velocity. Because the estimate is centred in the window it lags the newest sample by (filter_window_length - 1) / 2 samples (70 ms at 100 Hz with the default window of 15). The step \(dt\) of a call is the difference to the previous timestamp if given, else 1 / sampling_rate, else one second per sample.

output_type may be a list; the result then holds one output per type, in that order, all computed in the same pass and each identical to a Kinematics built for that type alone. The curvature-based smoothness index of a movement is a separate feature, CurvatureDispersion, fed with the velocity and acceleration vectors of this one (output_dims="components").

Parameters:
dimsint, optional

Number of components of a point: 1, 2 or 3. None (default) takes it from the first frame; a later frame of another size raises. (structural)

input_mode{“point”, “time_series”}, optional

"point" (default): one position per call, the feature keeps its own window. "time_series": a series of positions buffered by the caller per call. Kinematics.from_point(...) and Kinematics.from_series(...) build one or the other. (structural)

output_dims{“tangential”, “components”}, optional

"tangential" (default): each output is a scalar, the magnitude of the vector (the speed, for the velocity). "components": a (dims,) vector with the components x, y, z. A "direction" output is always a vector. (structural)

output_typestr or sequence of str, optional

What to compute: "smoothed" (the filtered position), "velocity" (default), "acceleration", "jerk", "curvature" or "direction", or a list of them. (structural)

filter_window_lengthint, optional

Samples of the Savitzky-Golay window; odd, greater than 3 and than filter_polyorder. Defaults to 15. (structural)

filter_polyorderint, optional

Order of the fitted polynomial. Defaults to 3. (structural)

movement_thresholdfloat, optional

Speed below which the point counts as still and the curvature is reported as 0, in m/s (scaled by units). Defaults to 0.005. (live)

sampling_ratefloat, optional

Sampling rate in Hz, used when no timestamp is given. Defaults to None (one second per sample, and the reason says so). (live)

units{“m”, “mm”}, optional

Unit of the position data. It scales movement_threshold and names the output units (m/s, mm/s, …); the data and the outputs are never scaled. Defaults to "m". (live)

Notes

Inputs. In "point" mode process(point, *, timestamp=None) takes one (D,) position per call and run(points, *, timestamps=None) a (T, D) recording. In "time_series" mode process(series) takes a (D, N) matrix, newest sample last, with N >= filter_window_length and the same N at every call; it describes the newest sample. timestamp is in seconds.

Outputs. One output per requested type, named after it: smoothed (unit of the data), velocity (unit/s), acceleration (unit/s^2), jerk (unit/s^3), curvature (1/unit; 0 below movement_threshold), direction (dimensionless unit vector). A scalar for output_dims="tangential", a (dims,) vector for "components" (direction always a vector).

Statuses. OK from the first sample on (the window is filled from the first call); INVALID_INPUT when the input or a result is not finite, or the timestamp does not increase. The first estimates, before the window holds filter_window_length real samples, are those of a partly filled window.

Corrected in the core: acceleration and jerk are the true second and third derivatives (they were the polynomial coefficients, half and a sixth of them); the 2D tangential curvature was too large by a factor \(\sqrt{2}\); the component curvature used a wrong normalisation. The estimate is the fit to the newest filter_window_length samples read at their centre; EyesWeb leaves the newest sample out of the fit, so its estimate lags one sample more.

Examples

>>> import numpy as np
>>> from pyeyesweb.low_level import Kinematics
>>> t = np.arange(100) / 100.0
>>> path = np.c_[0.5 * t, np.zeros_like(t)]  # 0.5 m/s along x, sampled at 100 Hz
>>> feature = Kinematics(sampling_rate=100.0, output_type="velocity")
>>> round(float(feature.run(path).velocity[-1]), 3)
0.5
