Migrating from 1.x#

PyEyesWeb 2.0 is a new library with the same aim as 1.x. It keeps the names of some features, but the call contract, the results, the parameters and the installation are different, and several features were removed. This page lists what changed and how to translate a 1.x script. “1.x” is the 1.1.1 release; “development” is an intermediate state of the work on 2.0 (some names that were in use only there are listed too, because notebooks and notes written during the development use them).

Note

pip install pyeyesweb installs 2.x. To keep a 1.x script running unchanged, install pyeyesweb<2.

What changed in one page#

The contract. In 1.x a feature was called with a SlidingWindow (feature(window)) or with an array (feature.compute(array)), and returned a feature-specific FeatureResult that could hold None. In 2.0 every feature declares its inputs, its outputs (a Schema) and its parameters before it sees data, and has the same three methods:

  • process(*sample, timestamp=None) takes one sample or frame and returns an immutable Result;

  • run(*recording, timestamps=None, reset=True) takes a whole recording and returns a Recorder, with the numbers of a loop of process;

  • reset() clears the state.

A feature that works on a window owns its buffer (window, hop): there is no SlidingWindow to fill. A result has a status (OK, WARMING_UP, NO_OUTPUT or INVALID_INPUT), a reason, a timestamp in seconds and one attribute per declared output; a value that was not produced is NaN, 0 or False, never None. latest holds the last OK result (None before the first one). See Inputs and Results, statuses and recorders.

The model. Features live in the packages of the layers of the conceptual model (physical_signals, low_level, mid_level, high_level, analysis_primitives), and pyeyesweb.catalog() lists the 60 of them. Time is in seconds, always passed as the keyword timestamp or timestamps; a rate is sampling_rate in hertz and has no default. Choices are lower-case strings, not enums. Joints are named (labels= or a skeleton= preset), not numbered. A parameter has one spelling in the whole library. See Time, units and parameters.

The install. The features run in a compiled core, the Python module eyesweb_core, which is a separate package from pyeyesweb. pip install pyeyesweb brings both; to work from a clone with a development build of the core, EYESWEB_CORE_PATH points at it (see Installation). import pyeyesweb, pyeyesweb.data_models and the enumerations Layer and Timescale work without the core; pyeyesweb.catalog() and the layer packages do not.

Five common usages, before and after#

The “before” code is 1.x (or development) code; it does not run with 2.0 and is not tested. The “after” blocks are run when the documentation is tested.

A window of samples#

Before (1.x): a SlidingWindow is filled by hand and passed to the feature.

from pyeyesweb.data_models import SlidingWindow
from pyeyesweb.low_level import DirectionChange

feature = DirectionChange(epsilon=0.5, num_subsamples=20, metrics=["cosine"])
window = SlidingWindow(max_length=20, n_signals=1, n_dims=2)
for point in trajectory:                  # one (x, y) per sample
    window.append(point)
    result = feature(window)              # or feature.compute(window_array)
    if result.is_valid:
        print(result.cosine)

After: the feature owns the window, and the first calls say that they are warming up.

>>> from pyeyesweb.low_level import DirectionChange
>>> angle = np.linspace(0, 2 * np.pi, 60)
>>> trajectory = np.c_[np.cos(angle), np.sin(angle)]       # one (x, y) point per row
>>> feature = DirectionChange(window=20, metrics=["cosine"], epsilon=0.5)
>>> feature.process(trajectory[0])
DirectionChangeResult(status=WARMING_UP, reason='1 of 20 samples', cosine=nan)
>>> recording = feature.run(trajectory)                    # the whole recording in one call
>>> recording
Recorder(DirectionChange, rows=60, columns=['cosine'], status={'OK': 41, 'WARMING_UP': 19})
>>> round(float(recording[-1].cosine), 4)
0.6441
>>> round(float(feature.latest.cosine), 4)                 # the last OK result
0.6441

Smoothness of a speed profile#

Before (1.x; SpeedSmoothness in development): one class computes up to seven metrics from a window of speeds.

from pyeyesweb.data_models import SlidingWindow
from pyeyesweb.low_level import Smoothness

smoothness = Smoothness(rate_hz=50.0, metrics=["sparc", "ldlj_v"])
window = SlidingWindow(max_length=60, n_signals=1, n_dims=1)
for speed in speeds:
    window.append(speed)
    result = smoothness(window)
    if result.is_valid:
        print(result.sparc, result.ldlj_v)

After: one class per metric, each with a required sampling_rate.

>>> from pyeyesweb.low_level import SpectralArcLength, LogDimensionlessJerk
>>> rate = 50.0
>>> time = np.arange(150) / rate
>>> speed = 0.6 * np.exp(-0.5 * ((time - 1.5) / 0.4) ** 2)
>>> sparc = SpectralArcLength(window=60, sampling_rate=rate)
>>> ldlj = LogDimensionlessJerk(window=60, sampling_rate=rate, input_mode="velocity")
>>> sparc.outputs, ldlj.outputs
(Schema(Output('spectral_arc_length')), Schema(Output('log_dimensionless_jerk')))
>>> first = sparc.run(speed, timestamps=time)[-1]
>>> second = ldlj.run(speed, timestamps=time)[-1]
>>> first.status.name, second.status.name
('OK', 'OK')

jerk_rms and samp_en are gone: use Kinematics(output_type="jerk") and SampleEntropy.

Synchronization#

Before (1.x): one class on a window of several signals, with a dictionary of filter parameters.

from pyeyesweb.analysis_primitives import Synchronization

sync = Synchronization(filter_params={"low": 1.0, "high": 10.0})
result = sync.compute(window_data)        # (time, signals, dims); result.plv

After: PhaseLockingValue takes the two signals as two inputs; the filter band is in hertz and needs sampling_rate.

>>> from pyeyesweb.analysis_primitives import PhaseLockingValue
>>> rng = np.random.default_rng(0)
>>> time = np.arange(500) / 50.0
>>> first = np.sin(2 * np.pi * 1.0 * time)
>>> second = np.sin(2 * np.pi * 1.0 * time + 0.5) + 0.1 * rng.normal(size=500)
>>> plv = PhaseLockingValue(window=200, hop=50, low_frequency=0.5, high_frequency=3.0, sampling_rate=50.0)
>>> plv.inputs
Inputs(first_signal: sample (1) - one value per call, second_signal: sample (1) - one value per call)
>>> recording = plv.run(first, second)
>>> recording
Recorder(PhaseLockingValue, rows=500, columns=['phase_locking_value'], status={'OK': 7, 'WARMING_UP': 199, 'NO_OUTPUT': 294})
>>> round(float(recording[-1].phase_locking_value), 3)
0.987

Choices: strings instead of enums#

Before (development): a choice was a member of an enumeration.

from pyeyesweb.low_level import KineticEnergy, KineticEnergyInputMode

energy = KineticEnergy(labels=labels, input_mode=KineticEnergyInputMode.VELOCITY)

After: a lower-case string, checked against the allowed choices; a constructor from_velocity is a shorthand.

>>> from pyeyesweb.low_level import KineticEnergy
>>> weights = {"hand": 1.0}
>>> energy = KineticEnergy(labels=["hand"], weights=weights, input_mode="velocity")
>>> energy.parameters["input_mode"]
'velocity'
>>> KineticEnergy.from_velocity(labels=["hand"], weights=weights).parameters["input_mode"]
'velocity'
>>> KineticEnergy(labels=["hand"], weights=weights, input_mode="speed")
Traceback (most recent call last):
    ...
ValueError: input_mode: invalid value 'speed'; choose one of 'position', 'velocity'
>>> energy.process(np.array([[3.0, 4.0, 0.0]])).kinetic_energy      # half of the weight times the squared speed
12.5

Joints: names and presets instead of indices#

Before (1.x): joints are positions in the array, and the reference is an index.

from pyeyesweb.low_level import GeometricSymmetry

symmetry = GeometricSymmetry(joint_pairs=[(4, 8)], center_of_symmetry=0)   # Kinect v2 indices
result = symmetry.compute(frame)          # frame: (n_joints, 3); result.pairs = {...}

After: a skeleton preset names the joints, and the pairs are pairs of names. The output is a score per pair, not an error (see the table of behaviour changes).

>>> from pyeyesweb.low_level import Symmetry
>>> frame = np.zeros((25, 3))                                  # the 25 joints of the Kinect v2 preset
>>> frame[4], frame[8] = (-0.2, 1.4, 0.0), (0.25, 1.4, 0.0)    # ShoulderLeft, ShoulderRight
>>> symmetry = Symmetry(skeleton="kinect_v2", method="reflection",
...                     pairs=[("ShoulderLeft", "ShoulderRight")], reference_point="SpineBase")
>>> symmetry.process(frame)
SymmetryResult(status=OK, pair_symmetry=[0.9824])

Presets are kinect_v2, qualisys_sport, mediapipe and openpose; see Map your marker set to a skeleton to map your own.

Renamed and removed names#

“1.x” in the second column means the name existed in the 1.1.1 release; “development” that it existed only in an intermediate state of the work on 2.0. Every old name was checked: it is not importable from 2.0, and every new name exists in the current release.

Parameter, input and output spellings#

A boolean output is always named is_<something>, the Savitzky-Golay parameters are always filter_window_length and filter_polyorder, and feature names have no Get prefix and no Index suffix. Behaviour changes that alter numbers#

A script ported name by name can still give different values. The first table lists what differs from 1.x or from the development states; the second lists corrections of defects of the original EyesWeb blocks, which apply to features that are new in 2.0 (each is also stated on the page of the feature, as “Corrected in the core”).

Feature

Change

SpectralArcLength, LogDimensionlessJerk, Harmonicity, SubmovementCount (1.x Smoothness)

the Butterworth low-pass filter (use_filter) is gone, so the values at the former defaults differ; the rate has no default

MultiScaleEntropy (1.x MultiScaleEntropyDominance)

sample entropy comes from the EyesWeb block; values differ from 1.x by a term of order 1/N

SampleEntropy

the default tolerance is relative to the signal (relative_tolerance=0.2); an absolute tolerance of 0.3 matched nothing on a signal of another scale and gave infinite entropies

Rarity

the EyesWeb block replaces the 1.x implementation, which computed a different quantity

Symmetry(method="reflection") (1.x GeometricSymmetry)

1.x gave the distance between a joint and the reflection of its partner (0 for a mirror image); 2.0 gives a score of the pair in [0, 1] that is 1 for a mirror image

Equilibrium

the margin is in metres (0.1 m, the former 100 mm); the three points are the inputs

only the total is returned; an empty frame is INVALID_INPUT instead of 0.0; weights is a mapping or one weight per label

BoundingBoxFilledArea, EllipsoidSphericity, PointsDensity

every feature

the step between samples is the difference of timestamps in seconds, the first call of a sequence uses 1 / sampling_rate, and without a rate it is one second per sample (the result says so in reason)

the running maximum was seeded with the smallest positive number, so a signal that stays at or below 0 never produced a peak

SilhouetteBodyParts, Videogram

the barycentre is the centroid of the mask truncated to whole pixels; the channel sums of the videogram are independent (the original aliased them)

GenericModelSimulator, HumanoidSimulator

the damping force is proportional to the relative velocity of the two masses (the original used speed magnitudes and injected energy); the feet of the T-pose are built along the direction they rest in

The notes on each family in the theory pages (Kinematics and energy, Smoothness, Impulsivity and suddenness, Humanoid and mass-spring models, Imaging) give the details.
