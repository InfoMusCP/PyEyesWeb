Changelog#

2.0.0#

PyEyesWeb 2.0 is a new library over a compiled port of the EyesWeb Expressive Gesture Analysis library. The migration table for every removed or renamed name is in the migration guide (docs/migration.md, “Migrating from 1.x”).

Breaking Changes#

  • feat!: new call contract, shared by all features. A feature declares inputs, outputs (a Schema) and parameters; process(*sample, timestamp=None) handles one sample or frame and returns an immutable Result, run(*recording, timestamps=None, reset=True) handles a whole recording and returns a Recorder, reset() clears the state, latest holds the last OK result (None before the first). FeatureResult, the per-feature result classes, compute(...), __call__(SlidingWindow) and SlidingWindow itself are removed; windowed features own their buffer (window, hop).

  • Result carries status (OK, WARMING_UP, NO_OUTPUT, INVALID_INPUT), reason, timestamp, a per-output valid mask and one attribute per output; is_valid remains as an alias of ok. A missing value is NaN (0 for integer and False for boolean outputs), never None, and array shapes do not change between calls.

  • feat!: layered architecture. Features live in pyeyesweb.physical_signals, low_level, mid_level, high_level and analysis_primitives; the catalog (pyeyesweb.catalog()) holds 60 features (11, 22, 7, 1 and 19). pyeyesweb.Smoothness and pyeyesweb.Synchronization are no longer exported at the top level.

  • The features run in a compiled core, the module eyesweb_core, a package separate from pyeyesweb (a development build is found through EYESWEB_CORE_PATH). import pyeyesweb, pyeyesweb.data_models and Layer work without it. The minimum supported Python version is 3.10.

  • Time rule and units: time is in seconds, keyword-only (timestamp, timestamps); sampling_rate in hertz replaces rate_hz and has no default; creation_time, time_mode and TICKS_PER_SECOND are gone. units="m" or "mm" scales the parameters, never the data.

  • Naming and signatures: one spelling per concept (number_of_inputs, window, cells_along_x, gaussian_sigma, gesture_duration, first_signal/second_signal, …; enforced by a test), choices are lower-case strings (no enumeration parameters), groups of boolean switches are parts=[...], joints are named (labels=, skeleton= presets) instead of indexed, signatures are explicit and keyword-only after window, hop.

  • The 1.x features were reshaped: Smoothness is SpectralArcLength, LogDimensionlessJerk, Harmonicity and SubmovementCount; Synchronization is PhaseLockingValue; GeometricSymmetry and SymmetryIndex3D are Symmetry; Impulsivity is SuddennessImpulsivity; MultiScaleEntropyDominance is MultiScaleEntropy plus EnsembleDominance; Rarity is the EyesWeb block; KineticEnergy, Equilibrium, DirectionChange and Suddenness have new signatures.

  • Removed: Lightness, Clusterability, StatisticalMoment, ZeroCross, CannyEdgeDetector, SkeletonManipulator, NoPreparationDetector and NoPreparationDetector2, MECS v1, EventSynchronizationRealTime, TauEstimator, ScalarBinarySyncDetector, the trajectory datatype and its blocks, the GeometricTrajectory3D transforms, pyeyesweb.utils.math_utils, pyeyesweb.utils.signal_processing and TSVReader. See the migration guide for the replacements.

Features#

  • feat: validation and INVALID_INPUT. NaN or infinite input, a missing joint and a timestamp that is not finite or not increasing give INVALID_INPUT with every output empty, and change no state (an overflowing result is also INVALID_INPUT, but is detected after the state advanced). Parameters are validated at construction and on assignment, and a rejected value leaves the feature unchanged.

  • feat: new and ported features, among them the imaging blocks (SilhouetteCentroids, SilhouetteBodyParts, Videogram, FilterContour, ContourCurvature, ConvexHull, BodyPartsFromCurvature, HitCellDetector, RegionDependingPotentials, PositionDependingPotentials), the humanoid and model blocks (HumanoidSimulator, HumanoidOrientations, GenericModelOrientations, GenericModelSimulator, GenericModelPredictor, GenericModelEstimator, PointsPredictor, MassSpringModel), the synchronization family (EventSynchronization, EventSynchronizationMECS, SpikeSynchronization, NonlinearInterdependence, PartialRecurrenceSynchronization, CorrelationsMatrix, GeneralisedAutoCorrelation, RecurrencePlot, CrossRecurrencePlot, TemporalSynchronization, SequenceDetector), Kinematics, Directness, TrajectoryNonPlanarity, CurvatureDispersion, CurvatureVelocityCorrelation, TriangleSymmetry, MotionNoiseDetector, GestureSegmenter, MotionDuration, ContractionImpulsivity, Periodicity, SampleEntropy, CoarseGraining, BinaryPulsesRegularity, ScalarPeakDetector and TimeWindowSynchronizer.

  • feat: KineticEnergy(input_mode="velocity") and a PCA fit of a point cloud in EllipsoidSphericity.process (with axis_ratio and radii), extensions of the EyesWeb blocks; the default behaviour is the faithful one.

  • feat: discovery metadata (LAYER, TIMESCALE, EYESWEB_BLOCK) on every feature class, pyeyesweb.catalog() and catalog_table().

  • feat: Result.to_array(), to_dict(), to_flat_dict(prefix, meta=True) and Recorder (preallocated columns, pandas to_frame(), rec[i] rebuilds a Result). Recorder.from_arrays and a C++ loop in KineticEnergy.run.

  • feat: live and structural parameters: feature.parameters is a read-only mapping, setters validate like the constructor, window and hop can change on a running feature, from_* constructors select an input mode.

  • feat: pyeyesweb.datasets (example recordings, optional datasets extra).

Behaviour changes#

  • Corrections of defects of the original EyesWeb blocks are the only behaviour (no fix_* flags); each is stated on the theory page of the feature as “Corrected in the core”.

  • Symmetry(method="reflection") returns a score in [0, 1] per pair instead of the distance of 1.x GeometricSymmetry.

  • The smoothness metrics (1.x Smoothness) no longer use the Butterworth pre-filter; MultiScaleEntropy values differ from 1.x by O(1/N); SampleEntropy uses a tolerance relative to the signal by default.

  • MotionNoiseDetector.is_noisy is True for noisy motion; CurvatureVelocityCorrelation velocities are per second; MassSpringModel.to_xml() writes relative damping (round trip).

  • Contraction features and KineticEnergy return INVALID_INPUT for an empty frame instead of 0.0; negative joint indices are no longer accepted.

Documentation#

  • The documentation is rebuilt with Sphinx and the PyData theme: concepts, theory pages with references, a user guide per layer, one generated API page per feature, how-to guides, a developer guide, a gallery of executed tutorials (sphinx-gallery) and a migration guide. Code blocks of the prose pages are executed by the documentation tests.

  • README.md and CITATION.cff are updated for 2.0.
