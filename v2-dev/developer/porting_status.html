Porting status#

PyEyesWeb is a Python layer over a compiled port of the EyesWeb Expressive Gesture Analysis library: the algorithms are ports of EyesWeb blocks, plus features of the laboratory that have no EyesWeb original. This page states the policy of the port, how a correction of the original is recorded, and which blocks of earlier versions are no longer in the library.

What the catalog holds#

>>> import pyeyesweb
>>> entries = pyeyesweb.catalog()
>>> len(entries), sum(info.eyesweb_block is not None for info in entries), sum(info.eyesweb_block is None for info in entries)
(60, 47, 13)

The first number is the number of features, the second the number that come from an EyesWeb block (the block is the EYESWEB_BLOCK of the class and the “EyesWeb” badge of its page), and the third the number of features of the laboratory, which have no original and are tested by their behaviour, by the catalog-wide suites and by frozen data.

Fidelity policy#

  • A port reproduces the original block: the same formulas, the same order of floating-point operations where it matters, the same defaults and the same edge cases. The EyesWeb source is the only authority; mathematics that is not in the original is not invented.

  • Hangs, crashes and undefined behaviour are not reproduced. The evident intent is implemented and the difference is described.

  • A deviation that changes numbers needs a decision of the maintainers. Until it is decided it is asked about and not guessed.

  • Once decided, the corrected behaviour is the behaviour of the core. There is no flag. No parameter that switches a correction on or off, such as a flag named legacy or compat, exists, and none is added; the numbers of an earlier behaviour are not available. A page and a docstring that describe a corrected behaviour mark it with the words Corrected in the core, followed by a one-line description.

  • A block that the maintainers retire is removed from the core, the bindings and the Python package together.

>>> import inspect
>>> flags = [(info.name, name) for info in entries for name in inspect.signature(info.cls).parameters
...          if name.startswith(("legacy", "compat")) or name.endswith("_fix")]
>>> flags
[]

A correction you can observe#

The default tolerance of SampleEntropy is relative to the scale of the signal. The absolute tolerance of the original matched nothing on a signal of another scale and gave infinite entropies; the corrected default gives a finite value whatever the scale.

>>> from pyeyesweb.analysis_primitives import SampleEntropy
>>> signal = np.random.default_rng(0).normal(size=1000) * 500.0
>>> entropy = SampleEntropy(window=200, hop=100, embedding_dimension=3).run(signal).sample_entropy
>>> bool(np.isfinite(entropy[~np.isnan(entropy)]).all())
True
>>> inspect.signature(SampleEntropy).parameters["tolerance"], inspect.signature(SampleEntropy).parameters["relative_tolerance"]
(<Parameter "tolerance: float | None = None">, <Parameter "relative_tolerance: float = 0.2">)

Where corrections are described#

Each correction is described where the feature is: in the Notes of its docstring, which the generated API page shows, and in the theory page of its family (Kinematics and energy, Smoothness, Shape, symmetry and balance, Impulsivity and suddenness, Gesture segmentation, Entropy, rarity and periodicity, Synchronization, Dominance, Humanoid and mass-spring models, Imaging). The corrections of the 2.0 release are also in the changelog (Changelog).

A change of the Python layer that alters numbers follows the same rule: it is a decision, it is documented in the docstring and in the changelog, and no test of numbers is edited to make it pass.

What is still open#

The skeleton presets qualisys_sport, mediapipe and openpose leave some fields empty (listed by Skeleton.missing()), to be filled by the maintainers (Map your marker set to a skeleton). The compiled core is its own package, eyesweb-core (Architecture and contract).
