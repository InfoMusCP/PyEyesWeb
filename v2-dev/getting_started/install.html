Installation#

Note

This documentation describes PyEyesWeb 2.0. The 1.x series has a different, incompatible interface: to keep a 1.x script running, install pyeyesweb<2, and to move it to 2.0 see Migrating from 1.x.

Requirements#

  • Python 3.10 or later (3.10 to 3.13 are declared; the documentation is built with 3.11).

  • NumPy and the compiled core, the package eyesweb-core. These are the only two runtime dependencies of PyEyesWeb, and pip installs both.

  • Optional: pandas for to_frame() of a Recorder, and matplotlib for the plots of the examples.

  • A platform for which a core wheel exists. The core is published as binary wheels for Windows, Linux and macOS; a development build has so far been used on Windows only.

PyEyesWeb is pure Python on top of a compiled core, which holds the numerical implementation of the EyesWeb blocks. The core is a separate wheel, eyesweb-core, that PyEyesWeb depends on (the 2.0 series of the core, the one the library was written for): there is nothing to compile.

Install#

pip install pyeyesweb

This pulls the eyesweb-core wheel with it. Optional extras: pyeyesweb[pandas] (for Recorder.to_frame()), pyeyesweb[datasets] (downloads of the example data) and pyeyesweb[test]. Use a virtual environment (python -m venv .venv) as for any scientific project.

Development install#

To work on PyEyesWeb itself, the library runs from a clone of the repository together with a development build of the compiled core, a folder that holds the core module. Two things must be visible to Python: the folder of the repository (the library), and the folder of the core, named by the environment variable EYESWEB_CORE_PATH.

git clone https://github.com/InfoMusCP/PyEyesWeb
$env:PYTHONPATH = "C:\path\to\PyEyesWeb"
$env:EYESWEB_CORE_PATH = "C:\path\to\core-build"
python -c "import pyeyesweb; print(len(pyeyesweb.catalog()))"

git clone https://github.com/InfoMusCP/PyEyesWeb
export PYTHONPATH=/path/to/PyEyesWeb
export EYESWEB_CORE_PATH=/path/to/core-build
python -c "import pyeyesweb; print(len(pyeyesweb.catalog()))"

EYESWEB_CORE_PATH is put first on sys.path when the library loads its core. If a different copy of the core was already imported from elsewhere, the library refuses to start rather than mix two builds.

Check the installation#

import pyeyesweb itself needs no core. catalog() does, because it imports every layer package: if it works, the library and the core are both in place.

>>> import pyeyesweb
>>> features = pyeyesweb.catalog()
>>> len(features)
60
>>> [info.name for info in features[:3]]
['HumanoidSimulator', 'HumanoidOrientations', 'GenericModelOrientations']

The catalog lists every feature with its layer and timescale (see Layers and the catalog).

The core version#

The library and the core are versioned together. Every layer package checks, at import, that the core reports the major and minor version the library was written for (2.0), and refuses to import otherwise. The version of the loaded core can be read from an internal module meant for diagnosis:

>>> from pyeyesweb._core import core, REQUIRED_CORE
>>> REQUIRED_CORE
(2, 0)
>>> core.__version__.split(".")[:2]
['2', '0']

The documentation footer shows the version of the core the pages were built with.

Error messages at import#

ImportError is the only exception raised while loading. It has one of four causes, each with its own text.

No core at all (the library cannot find the compiled module, and EYESWEB_CORE_PATH is unset or names a folder without it)

pyeyesweb features need the compiled EyesWeb core (the package eyesweb_core). Install it with `pip install eyesweb-core`, or set EYESWEB_CORE_PATH to the folder of a local build of eyesweb_core. Importing pyeyesweb, pyeyesweb.data_models, Layer and Timescale still works; catalog() and the layer packages (low_level, mid_level, …) raise it.

A core of another version

pyeyesweb needs eyesweb_core 2.0.x, but <file> is version 1.9.3 (build abc1234). Rebuild or reinstall the core. The version and build in the message are those of the module found. Install the core that matches the library.

A module named like the core, without a version

pyeyesweb needs eyesweb_core 2.0.x, but <file> is a module without a version (a stale or foreign build). Rebuild or reinstall the core.

A development path that conflicts with a core already loaded

EYESWEB_CORE_PATH is <path>, but eyesweb_core was already loaded from <file>. Remove the other copy from PYTHONPATH, or unset EYESWEB_CORE_PATH.
